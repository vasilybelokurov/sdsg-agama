# Maintaining sdsg-agama

Notes for the course lecturer (or whoever maintains this next). Students only need
[GUIDE.md](GUIDE.md). Written 2026-10-09.

## 1. How it fits together

```
GUIDE.md step 4:  pip install --no-index --find-links https://vasilybelokurov.github.io/sdsg-agama/ agama
                          |
                          v
docs/index.html (GitHub Pages)  -- links with #sha256=... -->  release "v1" assets (the wheels)
```

- **Release `v1`**: three wheels (Windows x64, macOS arm64, macOS x86_64) and `SHA256SUMS`.
- **Release `deps-v1`**: mirror of the pinned third-party source archives (GSL, Eigen); also
  serves as the GPL "corresponding source" for GSL.
- **`docs/index.html`**: generated by `build/make_index.py`; pip verifies each wheel's SHA-256
  from the link fragment. `--no-index` prevents pip from falling back to PyPI (where only a
  source distribution exists, which would try to compile AGAMA).
- **Do not delete or rename this repo, the `v1` release, or GitHub Pages**: step 4 of the guide
  depends on all three.

## 2. Workflows

| Workflow | Trigger | What it does |
|---|---|---|
| `build-test.yml` | every push; manual | Builds wheels on `windows-2022`, `macos-15`, `macos-15-intel`; tests each on fresh `windows-2022`, `windows-2025-vs2026`, `windows-11-vs2026-arm`, `macos-15`, `macos-26`, `macos-15-intel` in the student environment. Does **not** publish anything. |
| `guide-test.yml` | Mondays 06:00 UTC; manual | Follows GUIDE.md word for word on the same six runner types, installing from the **public** index. This is the check that the published install still works. |

Both run `tests/test_course.py` (19 analytic checks covering every AGAMA feature used in the
course notebooks; any failure fails the job) and `tests/smoke.ipynb` through Jupyter.

## 3. If the weekly `guide-test` fails

GitHub sends failure notifications for a scheduled workflow to the user who last edited its
`schedule` (here the repo owner), subject to your GitHub notification settings; failures are
also visible at <https://github.com/vasilybelokurov/sdsg-agama/actions>.

**Caveat:** GitHub disables scheduled workflows in public repos after 60 days without repository
activity. Before each term, check the Actions tab shows `guide-test` as enabled (re-enable it
there if needed) and run it once manually.

1. Open the failed job log and find the first error.
2. Most likely causes, in order:
   - **conda-forge changed a package** (e.g. a new numpy/matplotlib/jupyter build): the
     `conda create` or a test fails. Pin the offending package in the `conda create` line,
     **in GUIDE.md and in both workflows identically**, and re-run.
   - **A GitHub runner image changed or was retired** (e.g. `macos-15-intel`): update the
     runner label in both workflows. This does not affect students.
   - **Miniforge installer changed**: check GUIDE.md step 1 links still work.
3. If students are affected, tell them which line to change; the wheels themselves do not
   change unless you make a new release (section 4).

## 4. Making a new release (new AGAMA commit or Python version)

1. Put the new full commit SHA in `build/AGAMA_COMMIT`. Check whether AGAMA's `setup.py`
   still matches the anchors and URLs in `build/patch_setup.py` (run it on the new `setup.py`;
   it asserts on its anchors). If AGAMA now downloads different dependency versions, add their
   SHA-256 to `PINNED` and upload the archives to a new `deps-vN` release (and update `MIRROR`
   in `build/build_wheel.py`).
2. For a new Python version: change `3.12` in `build/build_wheel.py`, both workflows
   (`STUDENT_PKGS`, the guide-test `conda create` line and the Python checks), and GUIDE.md.
3. Push; wait for `build-test.yml` to pass on all 9 jobs. Do not release otherwise.
4. Download the tested wheels and publish:
   ```bash
   gh run download <run-id> -D dl
   mkdir -p relwheels && cp dl/*/*.whl relwheels/
   python3 build/make_index.py v2 relwheels/*.whl      # writes docs/index.html and SHA256SUMS
   gh release create v2 relwheels/*.whl SHA256SUMS --title "..." --notes "built in run <run-id>"
   git add docs SHA256SUMS && git commit -m "Publish v2" && git push
   ```
5. Wait for GitHub Pages to update, then run `guide-test.yml` manually
   (`gh workflow run guide-test.yml`) and check all six jobs pass.
6. Keep the old release until the new one is confirmed: students already installed are unaffected.

## 5. Decisions and why

| Decision | Reason |
|---|---|
| Prebuilt wheels instead of students compiling | Compiling needs Visual Studio Build Tools (several GB) or Xcode, a correctly initialised x64 MSVC prompt, and network access to the dependency hosts; for ~50 novices this was the main failure source. Reviewed with Codex (OpenAI) twice, which recommended the wheel route. |
| AGAMA pinned to `60d8d8b` (2026-07-23), not latest `f302756` (2026-08-25) | `f302756` replaced the cubature code and includes the POSIX header `alloca.h`; it does not compile with MSVC. `60d8d8b` keeps the long-used cubature implementation. |
| `/FIiso646.h` on Windows | `src/interface_python.cpp` uses the C++ alternative token `or`, which MSVC rejects by default; force-including `<iso646.h>` fixes it without editing AGAMA. |
| Dependencies prefetched, hash-pinned, mirrored on `deps-v1` | AGAMA's `setup.py` disables HTTPS certificate checks and fetches the Windows GSL over plain HTTP from `eugvas.net`, which returns HTTP 403 to GitHub runners. Every archive must match its pinned SHA-256 whichever source it comes from. |
| `setup.py` questions answered by policy (GSL Y, Eigen Y, CVXOPT N, UNSIO N) | `--yes` would answer yes to everything; CVXOPT (Schwarzschild modelling) and UNSIO (N-body I/O) are not used in the course. |
| macOS wheels without OpenMP, system libraries only | On CI, `setup.py` linked conda's `libomp`; bundling a second `libomp` next to numpy's risks the "OMP: Error #15" crash. Homebrew is hidden for the same reason and because its libraries would raise the minimum macOS to the build machine's. Course calculations are small; single-threaded is fine. |
| Windows wheel bundles `vcomp140.dll` (delvewheel, renamed `vcomp140-<hash>.dll`) | AGAMA uses OpenMP on Windows; the runtime is not guaranteed on student machines. CI checks the bundled copy is the one loaded. |
| Python 3.12, numpy 2.3 | `setup.py` imports `distutils` (removed from Python 3.12's standard library; provided by setuptools); 3.12 is supported until 2028. numpy is pinned so students get the version that was tested. |
| Windows on ARM via x64 Python | Windows 11 on ARM runs x64 programs by emulation (tested on `windows-11-vs2026-arm`). Windows 10 on ARM cannot run x64 programs and is unsupported. |

## 6. What has and has not been tested

- **Tested (2026-10-09):** `build-test.yml` run 37942374876 (commit `a7cf99a`) built the `v1`
  wheels and passed on all six test runners; `guide-test.yml` run 37947129762 passed on all six
  installing from the public index.
- **Not tested by CI:** real student laptops: antivirus software, OneDrive-redirected home
  folders, accounts without admin rights, university or eduroam networks, unusual usernames
  (spaces, non-ASCII characters), low disk space. A real-laptop check by a demonstrator or
  student is recommended before each class-wide release.

## 7. To report upstream (AGAMA, Eugene Vasiliev)

- `f302756`: `src/math_cubature.h` includes `<alloca.h>`, which does not exist with MSVC
  (`malloc.h` provides `_alloca` on Windows).
- `src/interface_python.cpp` uses the alternative token `or`; MSVC needs `<iso646.h>` or
  `/permissive-`.
- `http://eugvas.net/software/agama/gsl-master.zip` returns HTTP 403 to GitHub Actions
  runners, so `setup.py` on Windows fails there.
- Possibly of interest: official Windows/macOS wheels on PyPI would make this repo unnecessary.
